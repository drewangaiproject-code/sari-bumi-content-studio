# Initial Quality Checks

This file defines the first manual checks. It does not claim that automated tests have been implemented or passed.

## Repository structure
- [ ] The 15 approved paths exist.
- [ ] No unapproved files or copied legacy assets have been added.
- [ ] Links between the core documents resolve.
- [ ] Each role has a clear scope and approval boundary.

## Governance consistency
- [ ] Copy approval precedes visual production.
- [ ] QC pass is distinct from Owner final approval.
- [ ] Latest revision/withdrawal overrides older approval.
- [ ] No instruction authorizes Hermes or publishing as part of setup.

## Product safety and accuracy
- [ ] Provisional product facts remain marked pending until verified.
- [ ] No exhaustive ingredient claim is made without evidence.
- [ ] Product details are not mixed between SKUs.
- [ ] Unsupported medical, health, sensory, quality, or process claims are prohibited.

## Brand and asset handling
- [ ] Legacy assets are inventory-only during initial setup.
- [ ] Logo handling rules are consistent.
- [ ] Ingredient-count omission rule is documented.
- [ ] No public visual is treated as approved before Owner approval.

## Test reporting
Record checks as `PASS`, `FAIL`, or `NOT RUN`. Do not report a suite as passing unless it has actually been executed and its results inspected.
