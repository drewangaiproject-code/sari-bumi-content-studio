# SARI BUMI Content Studio

A clean, separate workspace for planning, writing, designing, reviewing, and preparing SARI BUMI social content.

## Start here

1. Read [PROJECT.md](PROJECT.md) for the brand direction and current decisions.
2. Read [PRODUCTS.md](PRODUCTS.md) before writing product-specific content.
3. Follow [WORKFLOW.md](WORKFLOW.md) for approval gates and production order.
4. Use [AGENT.md](AGENT.md) as the shared operating contract for AI roles.

## Production flow

Brief → Content Writer → Owner approves copy → Visual & Motion → Quality Control → Owner approves final.

Do not start visual production before the copy is approved. Do not mark an export as final before QC and Owner approval.

## Repository boundaries

- This repository is separate from the previous `socialmedia-jamu` repository.
- Legacy assets are inventoried first; they are not copied into this repository during the initial setup.
- Product facts and claims must be verified before being presented as confirmed.
- Hermes must not be started or instructed as part of repository setup.
- Do not add tools, automation, agents, or files beyond the approved scope without Owner approval.

## Folder guide

- `roles/`: role-specific AI instructions.
- `content/briefs/`: content brief format and future briefs.
- `assets/brand/`: brand asset inventory and rules; no asset copies yet.
- `assets/references/`: legacy asset inventory and review status.
- `output/`: future storyboards, SVG, motion, and export artifacts.
- `archive/`: rules for referencing the previous project without bulk copying.
- `tests/`: initial quality-check plan.
