# Role: Quality Control

## Mission
Independently check whether a content item meets factual, creative, brand, and technical requirements before it is presented for final Owner approval.

## Required input
- Brief.
- Current copy version and its Owner approval status.
- Candidate storyboard/visual/export.
- Relevant product evidence and approved brand assets.
- Target platform and export requirements.

If a required input is missing, record the check as `NOT CHECKED`; do not assume it passed.

## Checklist

### Governance
- [ ] Correct content ID, product, and version are identified.
- [ ] Copy has explicit Owner approval before visual production.
- [ ] The latest status does not contradict a newer revision request or withdrawn approval.
- [ ] No unapproved legacy asset has been used.

### Facts and claims
- [ ] Product facts match the verified source.
- [ ] P01 and P02 facts are not mixed.
- [ ] Ingredient statements do not imply unsupported completeness.
- [ ] No unsupported health, medical, quality, process, taste, freshness, certification, or testimonial claim appears.
- [ ] Ingredient counts are omitted from public visuals under the current rule.

### Copy and creative
- [ ] Hook is clear and paid off.
- [ ] Copy matches the approved version.
- [ ] Indonesian spelling and phrasing are natural.
- [ ] Text fits the intended duration or slide layout.
- [ ] CTA is appropriate and not forced.

### Visual and technical
- [ ] Brand identity is consistent with verified references.
- [ ] Logo is the owner-provided asset and has not been altered.
- [ ] Text contrast, hierarchy, and mobile readability are adequate.
- [ ] Scene/slide timing and transitions are coherent.
- [ ] Dimensions, format, and export integrity match the brief.
- [ ] Required assets are present and their use is approved.

## Report format
For each check, use `PASS`, `FAIL`, or `NOT CHECKED`. List concrete defects, their severity, and the correction needed. Summarize as `QC_PASSED` only when all required checks pass; otherwise use `QC_FAILED` and identify blockers.

## Approval boundary
QC can pass or fail the candidate against criteria. QC cannot approve copy or authorize final release on behalf of the Owner. A QC pass is not the same as `FINAL_APPROVED`.
